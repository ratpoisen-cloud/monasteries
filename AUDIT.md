## 3. 🔴 Критично

### 3.1. Класс `parchment-bg` не определён — экран победы и три модалки нечитаемы

Класс используется 4 раза, но правила `.parchment-bg` нет ни в `src/index.css`, ни где-либо ещё
(в CSS есть только `.parchment-codex`, `src/index.css:95`). Доказано компилятором Tailwind:
для кандидата `parchment-bg` CSS не генерируется, а `parchment-codex` — генерируется.

| Место | Что теряет фон | Что внутри |
|---|---|---|
| `src/App.tsx:217` | экран «Конец Летописи» | имя победителя, очки, кнопка «Начать заново» |
| `src/App.tsx:282` | диалог найма Дружинника в Крепости | кнопки «Нанять» / «Уйти» |
| `src/App.tsx:312` | диалог «Великий пожар» | выбор здания для сноса |
| `src/components/TradeModal.tsx:61` | вся Ярмарка | 7 слайдеров, сводка, «Подтвердить обмен» |

Текст в этих блоках — `text-amber-950` / `text-amber-900` (тёмно-коричневый) поверх `bg-black/40`
и `bg-black/85`. Итог: на экране победы, в Ярмарке, в Крепости и при пожаре текст практически
не виден, а кнопки не читаются. Тот же блок использует несуществующий `animate-scale-in`.

**Исправление:** заменить `parchment-bg` → `parchment-codex` (1 строка × 4 файла-места) либо
добавить `.parchment-bg` в `index.css`. Проверить визуально все 4 экрана.

## 4. 🟠 Высокий

### 4.1. Бурелом оставляет «призрак» фишки и рассинхронизирует движение
`src/stores/gameSlice.ts:634-660`

Ветка `windfall` переносит фишку в `prevCell`, но выставляет `hasEntered: false` (строка 652),
не убирая `occupantId` с клетки отступления. Воспроизведено на реальном сторе:

```
карта «Бурелом» -> клетки player_1: [(0,3:empty)]   hasEntered: false
   => фишка одновременно рисуется на клетке (Cell.tsx:199) и на стартовой площадке (Board.tsx:103)
вход через второй вход (0,4) -> клетки player_1: [(0,3:empty), (0,4:empty)]
   => ДВЕ клетки с occupantId одного игрока
findPlayerCell (rules.ts:52) возвращает (0,3) => движок считает текущей призрачную клетку
   => подсветка ходов строится вокруг (0,3), хотя фишка видна на (0,4)
```

Игрок может «вылечиться», кликнув по своей видимой клетке, но состояние доски повреждено,
правило «нельзя стоять на занятой клетке» обходится, а логика хода врёт.

**Исправление:** не сбрасывать `hasEntered`; оставить `hasEntered: true`, очистить `prevCell`
и не создавать вторую фишку (либо явно удалять `occupantId` с клетки отступления).

### 4.2. Устаревший результат кубика решает новую карту опасности
`src/stores/gameSlice.ts:407-432` (`drawEventCard` не сбрасывает `diceRollResult`),
`gameSlice.ts:733-734` (`monk_death_check` читает `get().diceRollResult`),
`src/components/EventModal.tsx:32-39`

Успешная переправа через реку (`gameSlice.ts:270-297`) оставляет `diceRollResult = 4`.
Если после этого на пустой клетке вытягивается «Кочевники/Язычники/Разбойники», модалка
считает, что бросок уже сделан (`hasRolled === true`), не показывает кнопку «Бросить кубик»
и выносит вердикт чужим числом:

```
вытянута карта: Лесные язычники | тип: monk_death_check
diceRollResult, который видит EventModal: 4  => кнопка броска скрыта
последняя запись в логе: «Четное число (4)! Монах благополучно преодолел опасность.»
```

Механика опасности (бросок, помощник, откуп, гибель) просто пропускается. Дефект латентно
опасен и в обратную сторону: при нечётном «залипшем» значении монах погибнет без броска.

**Исправление:** сбрасывать `diceRollResult: null` в `drawEventCard`, `executeCellAction` и
в начале каждой фазы хода; в `EventModal` привязывать бросок к конкретной карте (например,
хранить `rolledForCardId`).

### 4.3. Двойное списание ресурсов за время анимации кубика
`src/stores/gameSlice.ts:202-215` (ранний `return` при `diceRolling` не вызывает `onComplete`),
`gameSlice.ts:900-936` (Князь: списание 5 Молвы → бросок → фаза `BUILD` только в колбэке),
`gameSlice.ts:1028-1047` (Постриг: списание 3 Молвы + 1 Хлеба → бросок),
`src/components/MonasteryPanel.tsx:283` (кнопка не блокируется на время броска)

Кнопка «Выполнить действие» остаётся активной всю секунду анимации, а списание происходит
до броска. Воспроизведено:

```
visitCityLocation('prince') дважды: Молва 12 -> 2   (списано 10, бросок один)
recruitMonkAttempt дважды:          Молва 12 -> 5, Хлеб 6 -> 4, бросков 1
```

**Исправление:** `if (get().diceRolling) return;` в начале `visitCityLocation`/`recruitMonkAttempt`
(до списания) и `disabled={diceRolling}` на соответствующих кнопках.

### 4.4. Модалки выше экрана — кнопки недоступны на телефоне и ноутбуке
`src/components/TradeModal.tsx:60-61`, `src/components/EventModal.tsx:118-119`, `src/App.tsx:281,311`

Контейнер `fixed inset-0 flex items-center justify-center p-4`, у карточки нет `max-h`/`overflow-y-auto`,
высота содержимого Ярмарки (заголовок, цитата, баланс, 5 слайдеров, 2 степпера, 2 обмена, сводка,
кнопка) — порядка 900-950 px. При высоте окна меньше этого (телефон, 13" ноутбук в браузере)
верх и низ обрезаются: недостижимы ни «Подтвердить обмен», ни крестик закрытия; `body` не скроллится.
Оценка сделана по разметке (рендер-проверка в этом окружении невозможна).

**Исправление:** `max-h-[90dvh] overflow-y-auto` на карточке, блокировка скролла фона, `role="dialog"` + `Escape`.

### 5.2. Надёжность типов и краевые случаи
- **Нет `strict` ни в одном tsconfig** (`tsconfig.app.json`, `tsconfig.node.json` — флагов `strict`/`strictNullChecks`/`noUncheckedIndexedAccess` нет). Следствие: `players[activePlayerId]` (`App.tsx:95`) типизирован как `Player`, хотя рантайм может дать `undefined`, и это уходит в пропсы `player: Player` (`App.tsx:264,274`; `EventModal.tsx:9`; `TradeModal.tsx:6`).
- **Падение при `activePlayer === undefined`**: `EventModal.tsx:28` проверяет только `card`, а строка 30 уже читает `player.helpers`; `TradeModal.tsx:39` читает `player.resources`. Нужны guard'ы или `player?: Player`.
- **`initGame(5)`** создаёт игрока с `startCell: undefined` (`gameSlice.ts:98-138`, `rules.ts:44-49`) — при его ходе будет `TypeError`. UI ограничивает 2-4 (`App.tsx:182`), но защита нужна.
- **`endTurn` без проверки фазы** (`gameSlice.ts:1257`): вызов из любой фазы молча передаёт ход.
- **`initGame` не сбрасывает** `diceRolling`, `showTradeDialog`, `showFortressDialog`, `showDestructionDialog` (`gameSlice.ts:166-179`) → «Начать заново» может принести состояние из прошлой партии. Таймеры (`gameSlice.ts:206`, `App.tsx:142`) не отменяются: колбэк броска может записаться в новую партию.
- **Нет error boundary** — любой throw даёт пустой экран.
- **`TradeModal`** держит состояние слайдеров между открытиями (`TradeModal.tsx:26-34`, компонент не размонтируется) и после успешного обмена показывает прежние значения; `max={player.resources.salt - sellSalt - saltToWax}` (`:154,164`) может стать отрицательным → слайдер и сводка противоречат состоянию.
- **Закрытие Ярмарки крестиком** (`App.tsx:276`) не меняет фазу и не пишет в лог — выход только через «Пропустить».

### 5.3. Доступность и мобильный UX
