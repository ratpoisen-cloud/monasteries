## 1. Автотесты движка

**Цель:** любая правка правил ловится тестом, а не ручным прогоном.

**Проблема:** `npm ci` требует синхронного `package-lock.json`, а локально npm недоступен, поэтому
добавить vitest «в лоб» нельзя. Есть два пути.

### Вариант A (рекомендуемый) — без новых зависимостей
Прототип уже проверен в песочнице: компилируем стор и утилиты в CommonJS и гоняем встроенным раннером Node.

- [ ] `tsconfig.test.json`: `module: commonjs`, `moduleResolution: node`, `ignoreDeprecations: "6.0"`,
      `outDir: .test-build`, `include` — только `src/stores/**`, `src/utils/rules.ts`,
      `src/utils/deckGenerator.ts`, `src/types/**` (без `paths.ts` — там `import.meta`).
- [ ] `scripts/prepare-test-build.mjs` — пишет `.test-build/package.json` с `{"type":"commonjs"}`
      (иначе Node из-за `"type":"module"` в корне считает вывод ESM).
- [ ] `package.json`: `"test": "tsc -p tsconfig.test.json && node scripts/prepare-test-build.mjs && node --test tests/*.test.cjs"`.
- [ ] `.gitignore`: добавить `.test-build`.
- [ ] Тесты (по одному файлу на область) — `tests/*.test.cjs` на `node:test` + `node:assert/strict`.

**Набор тестов (12–15 кейсов, все уже проверены вручную):**

- [ ] CI: в `deploy.yml` шаг `npm test` перед `npm run build`.

убрать сброс `diceRollResult`) краснеет соответствующий тест.
**Риск:** низкий. Отдельно отмечу: `ignoreDeprecations` — временная мера, при переходе на TS 7
харнесс надо перевести на vitest.

### Вариант B — vitest (если готовы обновить lock-файл)
`npm i -D vitest`, тесты рядом с кодом, покрытие через `@vitest/coverage-v8`, в CI `npm test`.
Плюсы: нормальные матчеры, watch, покрытие. Минус: `package-lock.json` надо перегенерировать —
это делается одноразовым workflow `workflow_dispatch` в Actions (там npm есть) с коммитом лока.
Если выбираете B — сначала делаем этот одноразовый шаг, потом тесты.
